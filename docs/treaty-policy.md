# 등가성 협정 정책 — "여권"으로서의 라벨 (Treaty Policy v0.1)

> 라벨이 기관 안에서는 "신분증"이지만, 기관 사이를 오갈 때는 "여권"이다.
> 여권이 국경에서 통하려면 국가 간 협정이 필요하듯, 라벨이 타 기관
> 게이트에서 통하려면 **등가성 협정(treaty)** 이 필요하다.
>
> 본 문서는 Phase 1에서 정책을 설계·고정하고, 집행(검증 L3)은 Phase 2에
> 구현하기 위한 규격이다. 기계가독 형식: `deploy/treaties.demo.json`,
> 서빙: `GET /v1/treaties`.

## 1. 개념 대응

| 여권 체계 | LedgerMarker |
|---|---|
| 여권 | 라벨 (CMS SignedData) |
| 발행국 | 발급 기관 (issuerOrgId, 예: KPOST 우정사업본부) |
| 여권의 진위 확인 | 서명 검증 (발급 기관 CA 체인) |
| 입국 심사대 | 상대 기관 게이트 (CDS/DLP/AI필터) |
| 비자 협정 | 등가성 협정 (grade 번역표) |
| 입국 허가 결정 | 게이트 정책 (LM은 판정하지 않는다 — 불변식 4) |

## 2. 신뢰 수립 3단계

연동은 반드시 아래 순서를 밟는다. 각 단계는 독립적으로 폐기 가능하다.

```
[1단계] CA 교환         각 기관이 로컬에서 키 생성(lm pki init-org) 후
        (신뢰목록)       CA 인증서(공개)만 상호 전달 → lm trust import
                        → 상대 기관 라벨의 "서명 진위"를 검증할 수 있게 됨
[2단계] 협정 체결        등급 번역표를 협정문으로 작성, 양 기관
        (등가성 협정)    Treaty Signer가 각각 서명(Phase 2) → 상대 등급을
                        "우리 기준 무슨 등급인가"로 번역할 수 있게 됨
[3단계] 게이트 정책      번역된 등급에 대한 통과/차단 규칙은 각 기관
        (기관 자율)      게이트가 정한다 — LM 밖의 영역
```

**원칙 1 — 신뢰와 번역의 분리.** CA를 신뢰한다고 등급이 자동 연동되지
않는다(1단계 ≠ 2단계). 협정 없는 기관의 라벨은 "서명은 진짜"까지만
확인되고 `treaty: "absent"`로 응답한다.

**원칙 2 — 협정은 번역만 한다.** 협정은 "상대의 S는 우리의 S"라는
사실만 제공한다. 통과 여부는 게이트 정책이다(불변식 4). LM은 차단을
강제하지 않는다.

## 3. 협정문 규격

```jsonc
{
  "id": "kpost-mois-2026-01",        // 협정 식별자: <partyA>-<partyB>-<연도>-<회차>
  "partyA": "KPOST",                 // 기관 식별자 (issuerOrgId와 동일 체계)
  "partyB": "MOIS",
  "gradeMap": { "S": "S", "O": "O" },// partyA 등급 → partyB 등급 번역표
  "signedAt": "2026-09-01T00:00:00Z",
  "notAfter": "2027-08-31T23:59:59Z",// 협정 유효기간 (기본 1년, 자동 갱신 없음)
  "signature": "<base64>"           // Phase 2: 양측 Treaty Signer CMS 서명
}
```

- `gradeMap`은 **partyA→partyB 방향**으로 기술하고, 역방향은 역매핑을
  적용한다. 비대칭 번역(예: 상대 S → 우리 S이지만 우리 O → 상대 미인정)이
  필요하면 방향별 협정 2건을 체결한다.
- 번역표에 없는 등급은 번역 실패 → `treaty: "absent"` 처리. **기본
  허용(fail-open)으로 두지 않는다.**
- 협정 폐기는 삭제가 아니라 종료 이벤트로 기록한다(원장 원칙 준용,
  Phase 2에서 원장 이벤트 타입 확장 검토).

## 4. 검증 의미론 (L3 — Phase 2 집행 규격)

검증 요청의 라벨 발급 기관(issuerOrgId)이 검증 기관과 다를 때:

| 상황 | checks.treaty | translatedGrade | verdictHint 권고 |
|---|---|---|---|
| 유효 협정 있음 + 번역 성공 | `present` | 번역된 등급 | 게이트 정책 적용 |
| 협정 없음 / 만료 / 번역표에 없는 등급 | `absent` | (비움) | `review` |
| 자기 기관 문서 | `not_applicable` | 원 등급 | 통상 규칙 |

추가 규칙:

1. **PROVISIONAL은 여권이 아니다.** `approvalState=PROVISIONAL` 라벨은
   기관 내부 통행 전용이며 협정 번역 대상에서 제외한다 — 항상
   `treaty: "absent"` + `review`.
2. **폐기의 진실원천은 발급 기관 원장이다.** 상대 기관 문서의
   폐기·대체 여부는 발급 기관 원장 조회(또는 체크포인트 서명이 검증된
   미러)로 확인한다. 조회 불가 시 `ledger: "unavailable"`(판단 보류) —
   미등록과 혼동 금지.
3. **협정 서명 검증.** 협정문은 양측 Treaty Signer(§5.1 인증서 계층)의
   서명이 모두 유효할 때만 적용한다. 한쪽 서명 폐기 = 협정 효력 정지.
4. **감사 추적.** 협정 적용(번역)이 일어난 검증은 reasons에
   `treaty_translated:<협정id>`를 남긴다.

## 5. 실증(데모) 구성 — 우정사업본부 연동 기관

| 기관 ID | 기관명 | 연동 근거(데모 시나리오) |
|---|---|---|
| KPOST | 우정사업본부 | 자기 기관 (라벨 발급 주체) |
| MSIT | 과학기술정보통신부 | 상급 부처 — 정책·감사 문서 왕래 |
| MOIS | 행정안전부 | 정부 문서유통(문서24)·기록물 이관 |
| NTS | 국세청 | 우체국 금융·보험 과세자료 제출 |

각 기관 키는 `lm pki init-org`로 **각자 로컬 생성**하고, CA 인증서만
교환한다. 협정은 `deploy/treaties.demo.json`(전 등급 1:1 등가) —
실운영에서는 기관별 분류 기준 차이에 따라 번역표가 달라질 수 있다.
